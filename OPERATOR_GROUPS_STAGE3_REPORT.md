# Этап 3: «Прочитано ON/OFF» и автопрочтение по ответу

Статус: BUILD NOT RUN (в среде разработки нет Flutter). Тесты написаны, не запускались.

## Как было
Любое входящее сообщение от контакта делало прочитанными ВСЕ исходящие
в этом чате (`markOutgoingRead`). Именно это и запрещено ТЗ: «ответ — не любое
следующее сообщение».

## Что сделано
- **Миграция v4**: `messages.read_hold` (флаг «удерживать непрочитанным»).
- **Исходящее сообщение** (Исходящее, Отправка с статусами, фото/видео/голосовое
  «от владельца») получило переключатель **«Прочитано: ON / OFF»**
  (параметр действия `read`):
  - ON — сразу после выполнения сообщение прочитано;
  - OFF — сообщение «доставлено» и удерживается непрочитанным, пока контакт не
    ответит именно на него. Время «через сколько прочитано» при OFF не действует.
- **Входящее** (текст и медиа «от собеседника») получило поле **«Ответ на»**
  (параметр `replyToActionId`): выбор из исходящих сообщений этого участника
  выше по таймлайну. При выполнении:
  - новое сообщение получает `reply_to_id` — это существующая связь ответа
    (в чате ответ показывается цитатой);
  - выбранное исходящее становится прочитанным, флаг удержания снимается.
- **Любое другое входящее** не читает сообщения с OFF (удержание уважается и
  старой «общей» логикой, и импровизацией).
- **Связь «действие → сообщение»** хранится в журнале дубля и переживает
  перезапуск приложения (ответ находит своё сообщение).
- **«Назад» / «СБРОС СЦЕНЫ»** возвращают статус и флаг удержания.
- В строке таймлайна: «· прочитано» / «· не прочитано до ответа», «· ответ на сообщение».

## Совместимость
- Действия без настройки `read` (старые сцены) ведут себя как раньше:
  статус по полю «Статус», старое прочтение следующим входящим.
- В редакторе для старых действий переключатель выставляется по их прежнему
  поведению (прочитано, если статус «прочитано» или задано время прочтения).
  После сохранения настройка становится явной.
- Поле «Статус» у «Исходящего» заменено переключателем (ON = «прочитано»,
  OFF = «доставлено»).

## Не затронуто (осознанно)
- Сообщения «кто → кому» между профилями (`message`) — у них свой выбор
  статуса и события статуса по ссылке.
- Импровизация (`improv_sender`) по-прежнему читает исходящие ответом, но
  сообщения с OFF не трогает.
